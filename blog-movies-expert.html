Building a Movie Script RAG Chatbot with LangChain & Qdrant

A hands-on exploration of Retrieval-Augmented Generation - scraping real movie scripts, embedding them into a vector store, and answering questions with GPT-4o.

RAG LangChain Qdrant Python OpenAI GPT-4o Streamlit

Why I Built This

I wanted to learn Retrieval-Augmented Generation (RAG) - a technique that grounds an LLM's answers in a specific set of documents rather than its general training data. Instead of working with dry corporate documents, I picked something more fun: movie scripts. The project covers the full RAG pipeline from scratch - scraping, chunking, embedding, storing, retrieving, and generating answers via a chat interface.

The chatbot can answer questions about Star Wars: A New Hope, The Empire Strikes Back, Return of the Jedi, Deadpool, and Cars 2 - sourced directly from the original screenplay text.

How RAG Works

A plain LLM doesn't "know" the exact contents of your private documents - it can only draw on what it saw during training. RAG fixes this by adding a retrieval step: you first pull the most relevant text chunks from a vector store, then pass those chunks as context to the LLM alongside the user's question. The model synthesises an answer grounded in your actual source material.

User Question → Embed Query → Qdrant Vector Search
↓ top-k script chunks
Prompt (context + question) → GPT-4o → Answer

At indexing time, each script is scraped from the web, split into overlapping chunks (1000 chars, 200 overlap), embedded with text-embedding-3-small, and written to a local Qdrant collection. At query time the user's question is embedded the same way, the top 15 nearest chunks are retrieved, and those chunks are passed as context to GPT-4o for the final answer.

Libraries Used

langchain
Orchestration framework - chains, prompts, retrievers, and output parsers wired together with LCEL (LangChain Expression Language).
langchain-qdrant
LangChain integration for Qdrant. Wraps the vector store as a QdrantVectorStore and exposes a .as_retriever() interface.
qdrant-client
Python client for Qdrant. Used in local-persistence mode (QdrantClient(path=...)) - no server needed, data lives on disk.
langchain-openai
OpenAI integrations - ChatOpenAI (GPT-4o) for generation and OpenAIEmbeddings (text-embedding-3-small) for vectorisation.
langchain-text-splitters
RecursiveCharacterTextSplitter with scene-aware separators (\nINT., \nEXT.) to respect screenplay formatting during chunking.
requests + beautifulsoup4
Script scraping from imsdb.com - requests.get() fetches the page, BeautifulSoup extracts the raw <pre> screenplay text.
streamlit
Chat UI - st.chat_input, st.chat_message, and example-question buttons. @st.cache_resource keeps the RAG chain loaded across reruns.
python-dotenv
Loads the OPENAI_API_KEY from a local .env file so credentials stay out of the codebase.

Project Structure

The project is split into two files:

  • main.py - CLI version. Initialises the RAG chain and drops into an interactive input() loop.
  • app.py - Streamlit UI. Same RAG chain cached with @st.cache_resource, wrapped in a chat interface with a Star Wars-inspired dark theme.

Indexing Pipeline (runs once)

# 1. Scrape screenplay HTML → plain text Document
response = requests.get(url)
soup = BeautifulSoup(response.content, 'html.parser')
script_raw = soup.find('pre').get_text()
doc = Document(page_content=script_raw, metadata={"movie_title": title})

# 2. Chunk with scene-aware separators
splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000, chunk_overlap=200,
    separators=["\nINT.", "\nEXT.", "\n\n", "\n", " "],
)
chunks = splitter.split_documents([doc])

# 3. Embed + store in local Qdrant
vector_store = QdrantVectorStore.from_documents(
    chunks, path="./qdrant_db",
    collection_name="movie_scripts",
    embedding=OpenAIEmbeddings(model="text-embedding-3-small"),
)

RAG Chain (LCEL)

retriever = vector_store.as_retriever(search_kwargs={"k": 15})

rag_chain = (
    {"context": retriever, "question": RunnablePassthrough()}
    | ChatPromptTemplate.from_template(template)
    | ChatOpenAI(model="gpt-4o", temperature=0)
    | StrOutputParser()
)

The pipe operator (|) is LCEL - LangChain Expression Language. It composes retriever → prompt → LLM → parser into a single invokable chain, keeping the code clean and the execution lazy.

Key Design Decisions

Scene-aware chunking

Standard text splitters know nothing about screenplay format. By adding \nINT. and \nEXT. as high-priority separators, chunks tend to start at the beginning of a new scene rather than cutting mid-dialogue - which improves retrieval coherence.

Local Qdrant persistence

QdrantClient(path="./qdrant_db") stores the vector index on disk. The first run scrapes and embeds all five scripts (~a few minutes); subsequent runs skip straight to query mode. No Docker, no cloud account required - just a local folder.

Strict context grounding

The system prompt explicitly instructs GPT-4o to answer only from the retrieved script excerpts and to say "There is no information about this in the available movie scripts" if the context doesn't cover the question. This prevents the model from hallucinating answers from its general Star Wars knowledge.

What I Learned

This project made the RAG pattern very concrete. A few things that stood out: chunking strategy matters a lot - naive splits produce retrieval results that cut mid-sentence or mid-scene. The k parameter for the retriever is a real trade-off: more chunks means more context but also more noise for the LLM to reason over. And LCEL is genuinely elegant - building the retrieval-augmented chain as a single composable expression is far cleaner than wiring up callbacks manually.

The local Qdrant setup was also a pleasant surprise. Having a production-grade vector database running with zero infrastructure overhead is a great way to iterate quickly on small projects before committing to a cloud setup.

Next steps I'm considering: adding more films, streaming the LLM response token-by-token in Streamlit, and experimenting with re-ranking retrieved chunks before passing them to the prompt.
